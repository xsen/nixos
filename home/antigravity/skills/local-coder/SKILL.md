# Навык: Делегирование локальному кодеру (Local Coder & Hunk Sync)

Этот навык используется, когда пользователь явно просит поручить реализацию кода, рутинный рефакторинг или исправление тестов **локальной модели** (Qwen 3.8 / OpenCode), сохраняя роль **Tech Lead / Архитектора** за Antigravity (Gemini 3.8 Flash High).

---

## 🎯 Границы применения (Когда активировать):

* **АКТИВИРОВАТЬ:** Только если в запросе пользователя есть явный триггер:
  * «...через локального кодера»
  * «...отдай в opencode / запусти qwen»
  * «...делегируй локально»
  * «...поправь по hunk notes через локалку / qwen»
* **НЕ АКТИВИРОВАТЬ:** Если пользователь просит написать код без упоминания локального кодера. В стандартных случаях выполняй задачи напрямую в текущей сессии agy.

---

## 🏗️ Протокол взаимодействия

### Шаг 1. Архитектурная декомпозиция и ТЗ (`.agent/TASK.md`)
Локальной модели нужна однозначная постановка задачи. Никакой неопределенности:

1. Изучи кодовую базу проекта (структуру, типы, тесты).
2. При необходимости создай или обнови файлы типов/интерфейсов (`types.ts`, `models.py` и т.д.), задающие строгий контракт.
3. Сформируй файл спецификации `.agent/TASK.md` в корне рабочего проекта:
   * **Контекст**: краткая цель рефакторинга/фичи.
   * **Чек-лист шагов**: список конкретных файлов и методов для изменения.
   * **Команда проверки**: точная команда запуска тестов (например, `npm test`, `pytest`, `cargo test`).
   * **Критерий успеха**: все тесты должны проходить на 100% без изменения контрактов.

---

### Шаг 2. Запуск OpenCode в фоновом режиме
Перед запуском проверь, запущен ли локальный сервер инференса:
```bash
curl -s http://127.0.0.1:8080/health | grep -q '"status":\s*"ok"' || ai-local start
```

Запусти автономный прогон OpenCode через инструмент `run_command`:

```bash
opencode run --auto "Прочитай спецификацию .agent/TASK.md. Выполни все задачи по шагам, запусти тесты и убедись, что они завершаются со 100% успехом."
```

* **Важно**: используй параметр `--auto`, чтобы агент не застревал в ожидании интерактивного подтверждения разрешений.
* Если команда переходит в фоновый режим (background task), выведи пользователю краткое статусное сообщение и **заверши свой ход без вызова других инструментов**. Дождись системного уведомления о завершении таска.

---

### Шаг 3. Синхронизация с Hunk Diff
Когда фоновый процесс OpenCode завершился:

1. Проверь наличие живой сессии Hunk:
   ```bash
   hunk session list --json
   ```
2. Если сессия существует, мгновенно обнови diff в соседнем сплите Ghostty пользователя:
   ```bash
   hunk session reload --repo . -- diff
   ```
3. Сообщи пользователю статус: сколько тестов прошло, какие файлы изменились, и предложи взглянуть на diff в соседнем окне Hunk.

---

### Шаг 4. Обработка обратной связи через Hunk Notes (Human-in-the-Loop)
Если пользователь пишет: *«поправь по моим заметкам в Hunk»* или *«исправь замечания из hunk»*:

1. Запроси список пользовательских заметок через CLI:
   ```bash
   hunk session comment list --repo . --type user --json
   ```
2. Извлеки замечания: путь к файлу (`filePath`), номер строки (`newLine` / `oldLine`) и текст комментария (`summary`).
3. Дополни или перезапиши `.agent/TASK.md` конкретными пунктами исправлений по указанным строкам.
4. Снова запусти OpenCode по Шагу 2.
5. После исправления очисти отработанные пользовательские заметки или перезагрузи diff:
   ```bash
   hunk session reload --repo . -- diff
   ```

---

### Шаг 5. Интерактивное AI-Ревью в Hunk (по запросу)
Если пользователь просит: *«сделай ревью в Hunk»* или *«развесь замечания в diff»*:

1. Получи изменения через `git diff -U3`.
2. Добавь комментарии прямо в живое окно Hunk пользователя:
   ```bash
   hunk session comment add --repo . --file <путь> --new-line <строка> --summary "<текст замечания>"
   ```
3. При необходимости подсвети проблемный диапазон строки:
   ```bash
   hunk session highlight add --repo . --file <путь> --new-line <строка> --start <offset> --end <offset> --tone warning
   ```
